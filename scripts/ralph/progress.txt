## Codebase Patterns
- Vite defines `__COMMIT_SHA__` (see vite.config.ts `define`); the server already declares it in `src/server/env.d.ts`. The SPA-side declaration lives in `src/vite-env.d.ts` so it's visible to `tsconfig.app.json` (which excludes `src/server`).
- Tests live next to source as `*.test.ts(x)` and are picked up by `vitest run` (config in `vite.config.ts`). Always run `bun run test` in foreground only.
- App entrypoints: `src/main.tsx` wires global providers (ThemeProvider, SimulationProvider, then `<App />`); `src/app/App.tsx` owns the router and now the QueryClientProvider. Avoid moving the QueryClientProvider into main.tsx because App.test.tsx renders `<AppRoutes />` directly without it (no providers needed for current tests).
- Path alias `@/*` → `src/*` is configured in both tsconfig.app.json and vite.config.ts.
- `src/tests/setup.ts` only imports `@testing-library/jest-dom/vitest`; jsdom is the global env.
- Server-state hooks live in `src/lib/queries/*` (TanStack Query). queryKey convention: `['scenarios']` (list), `['scenario', id]` (detail), `['scenarios', scenarioId, 'payments']` via `paymentsQueryKey`. Mutations invalidate their list key in `onSuccess`. Plain `fetch` wrappers stay in `src/lib/api-client.ts` and are the queryFn bodies — don't call them directly from components, go through the hooks (or `useQueries` for dynamic lists).
- TEST GOTCHA: any test rendering a component that uses a TanStack hook (`useQuery`/`useMutation`/`useQueryClient`) — including anything under `<AppRoutes/>` or `<AppShell/>` (the shell mounts `MigrateLocalSimulationDialog`) — must wrap the render in `<QueryClientProvider client={new QueryClient({ defaultOptions: { queries: { retry: false } } })}>` or it throws "No QueryClient set".

- **Learnings for future iterations:**
  - The TanStack `persistQueryClient` API takes a single options object — the `dehydrateOptions.shouldDehydrateQuery` predicate is what controls per-query persistence (NOT a top-level filter).
  - To compare a queryKey against `['session']` in `shouldDehydrateQuery`, compare length + each element — `queryKey.includes('session')` is brittle if the key shape changes.
  - Module top-level side effects (`startQueryPersister()` in App.tsx) are safe here because `App.test.tsx` renders `<AppRoutes />` directly, never importing `App.tsx`. Keep that invariant in future stories that touch App.tsx.
  - When writing a vitest test that uses `vi.resetModules()` + dynamic `import()`, also re-import any sibling module whose identity matters (`queryClient` here), otherwise referential equality checks fail because the top-level import captured the pre-reset instance.
  - For React Query v5, `gcTime` replaces v4's `cacheTime`. Use `gcTime` directly in defaults.

- **Learnings for future iterations:**
  - O `QueryClientProvider` de produção vive em `src/app/App.tsx` (acima do `BrowserRouter`), NÃO em main.tsx nem em AppRoutes. Qualquer teste que renderize `<AppRoutes/>`, `<AppShell/>` ou um componente do feature `historico` precisa envolver o render num `<QueryClientProvider client={new QueryClient(...)}>`, senão `useQueryClient` lança "No QueryClient set". Use `{ defaultOptions: { queries: { retry: false } } }` nos testes para falhar rápido.
  - Convenção de queryKeys deste app: scenarios → `['scenarios']`; detalhe → `['scenario', id]`; pagamentos de um cenário → `['scenarios', scenarioId, 'payments']` (via helper `paymentsQueryKey`). Mantenha mutations invalidando essas chaves no `onSuccess`.
  - Para listas dinâmicas (N cenários → N consultas de pagamentos) use `useQueries` chamando a função plain `listPayments` no `queryFn` (compartilha o mesmo `paymentsQueryKey` que `usePayments`), em vez de useEffect manual.
  - `useScenarios` aceita `{ enabled }` para preservar o lazy-load do `ScenarioCombobox` (só busca após o primeiro open). Com cache do TanStack, abrir o dropdown várias vezes dispara o fetch só uma vez — o teste "does not refetch on subsequent opens" valida isso sem `vi`.
  - `MigrateLocalSimulationDialog` agora usa `useCreateScenario()`; como ele é montado no `AppShell`, o teste `financiamento-page.test.tsx` (que não mocka api-client) passou a precisar do provider.
