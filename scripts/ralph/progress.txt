## Codebase Patterns
- **Worker vs SPA TypeScript split**: `src/server/` is excluded from `tsconfig.app.json` and typechecked via `tsconfig.server.json` with `types: ["@cloudflare/workers-types"]`. This keeps DOM lib out of the worker compile and avoids conflicting global types. Add new server code under `src/server/` and it gets picked up automatically.
- **Worker bindings live in `src/server/env.d.ts`** (`interface Env`). Hono routes type the env via `new Hono<{ Bindings: Env }>()`. Add every new binding/secret here _and_ wire it into `wrangler.jsonc` (`vars` for plain values, `wrangler secret put` for secrets, `d1_databases` for D1).
- **Build output structure under cloudflare/vite-plugin**: `bun run build` writes the SPA to `dist/client/` and the bundled worker + generated wrangler config to `dist/calculadora_financeira/`. The plugin rewrites paths so `wrangler deploy` uses the redirected config — never point wrangler at the source `wrangler.jsonc` directly.
- **Cloudflare custom_domain routes do NOT accept wildcards or paths.** Use `{ pattern: "calculadorafinanceira.app", custom_domain: true }`, not `calculadorafinanceira.app/*`.
- **Node 20 in the sandbox can't run wrangler directly** (needs v22). Always invoke via `bunx --bun wrangler ...` so the bun-bundled runtime is used.
- The `migrations/` directory must exist (even if empty with a `.gitkeep`) because `wrangler.jsonc` references `migrations_dir: "migrations"`.
- **Better Auth on D1**: `betterAuth({ database: env.DB })` is enough — the kysely-adapter auto-detects D1 via `batch/exec/prepare` and dynamically loads `D1SqliteDialect`. No `{ provider: 'd1' }` wrapper needed in v1.6.x. Build a fresh `createAuth(env)` per Hono request (no module-level singletons in Workers — each request has its own bindings).
- **Shared auth options pattern**: keep plugin/session/email options in `src/server/auth-options.ts` (no env deps) and re-use them in both `src/server/auth.ts` (Worker, `database: env.DB`) and `auth.config.ts` (CLI, in-memory SQLite). Prevents the CLI-generated schema from drifting from the runtime config.
- **`@better-auth/cli generate` needs a real Kysely-compatible DB** because it calls `db.introspection.getTables()`. Bun runs the CLI through jiti/Node, so `bun:sqlite` is unavailable there; the fallback is to install `better-sqlite3` (native build) or hand-write the SQL using `@better-auth/core/db/get-tables` as the source of truth. The hand-written `0001_better_auth.sql` mirrors the Kysely SQLite output exactly: lowercase DDL keywords, double-quoted identifiers, `text`/`integer`/`date` types, `references "user" ("id") on delete cascade`, indexes appended as `create index "<table>_<col>_idx"`.
- **Hono middleware registration order matters**: `app.use(path, mw)` only applies to handlers registered AFTER the `use` call. Put public routes first, then `app.use(requireUser)`, then protected routes. The `/api/*` 404 fallback can sit after the middleware safely (returns 401 for unauthed unknown routes — fine).
- **Server-side vitest pattern**: tests under `src/server/**` are picked up by `tsconfig.server.json` (workers-types only, no DOM lib). Import everything explicitly from `vitest` (no globals), mock dependencies with `vi.mock("../auth", () => ({...}))` at module top, and use Hono's `app.request(path, init, env)` to drive the middleware with a fake `Env`. Hono serializes `Date` to ISO strings when round-tripping through `c.json`, so assertions must compare `.toISOString()`.

- **Learnings for future iterations:**
  - The kysely-adapter's D1 path is detected purely by duck-typing the binding (`"batch" in db && "exec" in db && "prepare" in db`). Passing `env.DB` directly works in v1.6.x; the PRD's `{ provider: 'd1', binding: env.DB }` syntax is not supported and will type-error. Update later PRD entries that still use that form (e.g. US-004's surrounding context).
  - `bun add @better-auth/cli` triggers a peer install of `better-sqlite3`, which requires `node-gyp` and a CXX toolchain. Use `--ignore-scripts` to install the CLI in sandboxes without native build deps; the CLI's `generate` command still won't work without a real SQLite (bun-sqlite OR better-sqlite3 native), but the package install succeeds.
  - When hand-writing migrations to match the better-auth schema, use `@better-auth/core/dist/db/get-tables.mjs` as the source of truth. Each field has `type` (string|boolean|number|date|json), `unique`, `required`, `references`, `index`, and a `fieldName` (camelCase). Boolean → `integer`, date → `date`, string|references → `text`. Indexes only emit for fields with `index: true` (and inherit `unique` if both are set).
  - `@better-auth/cli/dist/generators-*.mjs::generateKyselySchema` joins compiled statements with `;\n\n` and ends the file with `;`. My hand-written SQL uses one statement per `CREATE TABLE`/`CREATE INDEX` separated by blank lines — wrangler's SQL parser handles both forms.
  - The Worker bundle pulls in three SQLite dialects (D1, Bun, Node) because the kysely-adapter `await import()`s them conditionally. That's fine on Workers (dead-code at runtime), but bundle size jumps ~1.4 MiB. Watch this if we get near the 10 MiB free-tier limit.
  - `useDefineForClassFields` + `noUncheckedSideEffectImports` in tsconfig.app.json conflict with raw side-effect imports; keep server-only code in `src/server/` so it lands in `tsconfig.server.json` (which doesn't have the DOM lib and so won't reject worker types).
  - The custom auth.config.ts at the repo root is NOT included in any tsconfig (intentional — Bun runs it directly). If you ever need to typecheck it, add a fourth project ref; for now `@ts-ignore` on the `bun:sqlite` import is sufficient.

- **Learnings for future iterations:**
  - Hono's `createMiddleware<{ Bindings; Variables }>` is the cleanest way to type a middleware that needs both env bindings and shared context variables. The Variables type is the canonical place to declare what `c.get(...)` returns inside route handlers downstream.
  - Better Auth's `auth.api.getSession` returns `null` for missing/expired/revoked sessions (no thrown error in the happy "no session" path). Wrap it in try/catch anyway — D1/network failures during the lookup should not 500; they should fail closed as 401.
  - Hono's route dispatcher composes ALL matched handlers/middlewares in registration order. A `use()` registered AFTER a `get()` does NOT wrap the earlier handler. This makes `/api/health` and `/api/auth/*` trivially "public" — just register them before `app.use(requireUser)`.
  - Mock Better Auth in tests by `vi.mock("../auth", () => ({ createAuth: vi.fn() }))`. The factory must return something whose `.api.getSession` is a function — Hono will only ever invoke that path. Cast through `as unknown as ReturnType<typeof createAuth>` to satisfy TS without pulling the full Better Auth surface.
