## Codebase Patterns
- Vite defines `__COMMIT_SHA__` (see vite.config.ts `define`); the server already declares it in `src/server/env.d.ts`. The SPA-side declaration lives in `src/vite-env.d.ts` so it's visible to `tsconfig.app.json` (which excludes `src/server`).
- Tests live next to source as `*.test.ts(x)` and are picked up by `vitest run` (config in `vite.config.ts`). Always run `bun run test` in foreground only.
- App entrypoints: `src/main.tsx` wires global providers (ThemeProvider, SimulationProvider, then `<App />`); `src/app/App.tsx` owns the router and now the QueryClientProvider. Avoid moving the QueryClientProvider into main.tsx because App.test.tsx renders `<AppRoutes />` directly without it (no providers needed for current tests).
- Path alias `@/*` → `src/*` is configured in both tsconfig.app.json and vite.config.ts.
- `src/tests/setup.ts` only imports `@testing-library/jest-dom/vitest`; jsdom is the global env.
- Server-state hooks live in `src/lib/queries/*` (TanStack Query). queryKey convention: `['scenarios']` (list), `['scenario', id]` (detail), `['scenarios', scenarioId, 'payments']` via `paymentsQueryKey`. Mutations invalidate their list key in `onSuccess`. Plain `fetch` wrappers stay in `src/lib/api-client.ts` and are the queryFn bodies — don't call them directly from components, go through the hooks (or `useQueries` for dynamic lists).
- TEST GOTCHA: any test rendering a component that uses a TanStack hook (`useQuery`/`useMutation`/`useQueryClient`) — including anything under `<AppRoutes/>` or `<AppShell/>` (the shell mounts `MigrateLocalSimulationDialog`) — must wrap the render in `<QueryClientProvider client={new QueryClient({ defaultOptions: { queries: { retry: false } } })}>` or it throws "No QueryClient set".
- Session = `useSession()` from `src/lib/queries/session.ts` (TanStack, queryKey `['session']`). It's the ONLY session source in app code — returns `{ user, session, isPending, isError }`, `null` response → `{ user: null, session: null }`. Sign-out is `useSignOut()` (POST /api/auth/sign-out → invalidates `['session']`). `@/lib/auth-client` (the Better Auth client) is reserved for the auth forms under `src/features/auth/**` (sign-in/up/reset) + the type re-exports in `session.ts`/`api-client.ts`. Don't reintroduce `use-current-user`.
- TEST GOTCHA: when a test mocks `@/lib/queries/session`, the factory must export EVERY function the rendered tree calls. `NavUser` calls both `useSession` AND `useSignOut`; since `AppSidebar`/`AppShell` render `NavUser`, those tests' mocks need `useSignOut: () => ({ mutate: vi.fn() })` too — otherwise "No useSignOut export is defined on the mock". Mocks return the flattened `{ user, session, isPending, isError }` shape, not a raw `UseQueryResult`.
- Better Auth: `createAuth(env)` (in `src/server/auth.ts`) runs fine with a fake `DB: {} as D1Database` (init is lazy w.r.t. queries) and the returned instance exposes the RAW options passed to `betterAuth()` on `.options`. So server tests can assert config (e.g. `createAuth(env).options.socialProviders`) by calling the REAL `createAuth` — no need to mock `betterAuth`. Mocking `better-auth` is risky because `better-auth/api` (`createAuthMiddleware`, used in the before-hook) imports from it.
- Env-gated UI (e.g. `VITE_GOOGLE_ENABLED`): read `import.meta.env.X` AT RENDER (inside the component), not in a module-top const — only then does `vi.stubEnv('X','true')` (+ `vi.unstubAllEnvs()` in afterEach) take effect in tests. Keep the gating + any sibling markup INSIDE the component and export only the component, to avoid the `react-refresh/only-export-components` warning.
- KNOWN FLAKY (under heavy load only): the full `bun run test` can exit code 1 due to ~4 post-teardown "Unhandled Rejection: BetterAuthError: Failed to initialize database adapter" from `src/server/auth-google.test.ts`, even with all tests passing. It passes 4/4 in isolation (`vitest run src/server/auth-google.test.ts`). It's a lazy D1-adapter init race in the REAL `createAuth`, not a real failure.
- D1 migrations: lowercase SQL with double-quoted identifiers; FKs are `references "user" ("id") on delete cascade` (the Better Auth user table is `"user"`). Apply locally with `bunx --bun wrangler d1 migrations apply calculadora-financeira-db --local` (or `bun run db:migrate:local`); migrations live in `migrations/` (configured in wrangler.jsonc). Files are numbered `000N_name.sql`.
- D1 upsert pattern (SQLite): `insert into "t" (...) values (?,?) on conflict("pk_col") do update set "c" = excluded."c"`. Use this for one-row-per-user / one-per-key tables.
- Tracker schema (migration 0005): `tracker_plans` (one per plan, FK `user_id`→`"user"`) + `tracker_entries` (FK `plan_id`→`tracker_plans`, `unique(plan_id, month_index)`). Money in `*_cents`, rate in `annual_rate_bp` (basis points). Enum-ish columns use SQLite `check(... in (...))`: `modality in ('PRICE','SAC')`, `apply_mode in ('reduce_term','reduce_installment')`. Indexes: `tracker_plans_user_id_idx`, `tracker_entries_plan_id_idx(plan_id, month_index)`. So US-010/011 routes must convert BRL→cents and %→bp like scenarios.ts before insert.
- Server route ordering GOTCHA: in a Hono sub-app, register STATIC paths (e.g. `get("/draft")`) BEFORE param paths (`get("/:id")`) so the static path wins. Sub-apps mounted in `src/server/index.ts` that bring their own `requireUser` must be mounted BEFORE the generic `app.use("/api/*", requireUser)`; more specific mount paths (e.g. `/api/scenarios/:scenarioId/payments`) go before less specific (`/api/scenarios`).
- Tracker routes status codes (US-010/011): validation failures (Zod + business rules like downPayment>=propertyValue, paid_amount<parcela) return **422** (NOT 400 like scenarios/payments). Malformed JSON still returns 400 (`invalid_json`). `GET /api/tracker/plans/:id` returns `{ plan, entries }`; ownership is enforced via `and "user_id" = ?` in the SELECT → 404 when not owned. PUT edits only name + target_monthly_total (term/property/modality immutable). Mount order in index.ts: tracker-entries (`/api/tracker/plans/:planId/entries`) BEFORE tracker-plans (`/api/tracker/plans`), both before the generic `app.use("/api/*", requireUser)`.
- Server test FakeD1 (`src/server/routes/*.test.ts`): a hand-rolled in-memory D1 stub whose `prepare(sql)` dispatches on `sql.startsWith(...)` and THROWS on unrecognised SQL — so any new query needs a matching branch in `run()`/`first()`/`all()`, or the test fails loudly. `buildApp(userId)` mocks `createAuth` to return a fake session; the 401 path mocks `getSession: async () => null`.
- PROVIDER ORDERING GOTCHA: `SimulationProvider` is mounted in `src/main.tsx` ABOVE `<App/>`, and `App.tsx` is where `<QueryClientProvider>` lives. So `SimulationProvider` sits ABOVE the QueryClient and CANNOT use TanStack hooks (`useSession`/`useQuery`). Any simulator code that needs server-state must run in a component BELOW the routes (e.g. inside `FinancingForm`, which is rendered by `FinanciamentoPage`), not in the provider. This is why `useSimulatorDraft` lives in the form, not the provider.
- Simulator draft autosave: `src/features/simulator/lib/simulator-draft.ts` owns the `FinancingDraft` type + localStorage helpers (key `sim-draft-v1`). `useSimulatorDraft()` (in `src/features/simulator/hooks/`) restores (localStorage sync first render; D1 `GET /api/scenarios/draft` preferred once it resolves for logged-in users, guarded so a late query never overwrites typed input) and debounce-saves (localStorage always + D1 PUT when logged in). The draft payload is the RAW financing form input (partial/invalid OK), not validated `FinancingFormValues`.
- Server can import the finance engine: server route files (`src/server/**`) may import `@/core/finance/*` (the `@/`→`src/*` alias is configured in tsconfig.server.json paths AND vite.config.ts resolve.alias, so typecheck, vitest, and the worker bundle all resolve it). Reuse `generatePriceSchedule`/`generateSacSchedule` (from `@/core/finance/amortization`) + `annualToMonthlyRate` (from `@/core/finance/rent-vs-buy`) instead of duplicating amortization math. Unit conversion to feed the engine from a tracker plan row: `principal = (property_value_cents - down_payment_cents)/100`, `monthlyRate = annualToMonthlyRate(annual_rate_bp/10000)`; the schedule installment is BRL Decimal (2dp), so `installmentCents = round(installment.times(100))`.
- Tracker entries (US-011): mounted at `/api/tracker/plans/:planId/entries` BEFORE `/api/tracker/plans` in index.ts. The `:planId` param is read inside the sub-app via `c.req.param("planId")` (same trick as payments' `:scenarioId`). Ownership = `select * from "tracker_plans" where "id" = ? and "user_id" = ?` (full row, since installment validation needs modality/term/rate) → 404 if not owned. POST is an UPSERT (`on conflict ("plan_id","month_index") do update set ...` keeping id+created_at), returns **200** (NOT 201) with `{ entry }` (re-selected after upsert). Hard rule: `paid_amount_cents >= normalSchedule installment of that month` → else **422** (pt-BR message). PATCH edits paid_amount/apply_mode/note only (never month_index); when paid_amount changes it re-validates against the installment for the EXISTING row's month_index.
