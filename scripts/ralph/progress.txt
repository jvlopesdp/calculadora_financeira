## Codebase Patterns
- **Worker vs SPA TypeScript split**: `src/server/` is excluded from `tsconfig.app.json` and typechecked via `tsconfig.server.json` with `types: ["@cloudflare/workers-types"]`. This keeps DOM lib out of the worker compile and avoids conflicting global types. Add new server code under `src/server/` and it gets picked up automatically.
- **Worker bindings live in `src/server/env.d.ts`** (`interface Env`). Hono routes type the env via `new Hono<{ Bindings: Env }>()`.
- **Build output structure under cloudflare/vite-plugin**: `bun run build` writes the SPA to `dist/client/` and the bundled worker + generated wrangler config to `dist/calculadora_financeira/`. The plugin rewrites paths so `wrangler deploy` uses the redirected config — never point wrangler at the source `wrangler.jsonc` directly.
- **Cloudflare custom_domain routes do NOT accept wildcards or paths.** Use `{ pattern: "calculadorafinanceira.app", custom_domain: true }`, not `calculadorafinanceira.app/*`.
- **Node 20 in the sandbox can't run wrangler directly** (needs v22). Always invoke via `bunx --bun wrangler ...` so the bun-bundled runtime is used.
- The `migrations/` directory must exist (even if empty with a `.gitkeep`) because `wrangler.jsonc` references `migrations_dir: "migrations"`.

- **Learnings for future iterations:**
  - When wrangler complains about Node 20, use `bunx --bun wrangler ...` instead of direct `wrangler`. The script `deploy:dry-run` invokes wrangler directly, so it fails locally with Node 20; CI will be fine on Node 22 (US-038).
  - The `cloudflare` plugin moves the SPA from `dist/` to `dist/client/`. If any existing tooling assumed `dist/index.html` is the SPA index, it now needs updating to `dist/client/index.html` (currently no code depends on this).
  - `custom_domain` routes cannot contain `/*` or path segments — Cloudflare validates at deploy time. PRD wording was technically invalid; corrected in implementation and noted in PRD `notes`.
  - `assets` + `routes` work together: the asset binding handles static files and the SPA fallback (`not_found_handling: "single-page-application"`); the worker handles `/api/*` and any explicit route handler that returns before falling through.
