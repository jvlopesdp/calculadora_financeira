## Codebase Patterns
- Static assets live under `public/` (Vite default `publicDir`; there is no explicit `publicDir` in vite.config.ts). Files in `public/` are copied verbatim to `dist/client/` at build. Reference them by absolute path from the SPA (e.g. `/brand/icon.svg`).
- Build is `tsc -b && vite build` via the @cloudflare/vite-plugin; **vite build is SLOW (~6 min)** because it bundles xlsx + fonts. Run builds in background and poll the process, not the output file (output is buffered until the end).
- `bun run typecheck` = `tsc -b --noEmit`; `bun run lint` = `eslint .`; `bun run test` = `vitest run` (foreground only).
- `Env` (`src/server/env.d.ts`) has all-required fields. Adding a new required field breaks every fake-`Env` in `src/server/**/*.test.ts` — grep `BETTER_AUTH_URL:` and add the field next to it in each.
- Server auth/url logic is written as pure exported helpers and unit-tested directly (never instantiate `betterAuth()` — it starts a background D1 init promise that rejects with a fake DB). See `googleSocialProvider`, `buildVerificationUrl`, `buildResetUrl` in `auth.ts`.
- `wrangler` CLI requires Node >= 22; the local sandbox runs Node 20, so `wrangler deploy --dry-run` ACs cannot be executed here — defer to CI.
- Rasterize brand SVGs with ImageMagick: `convert -background none -density 300 -resize WxH in.svg out.png` (`/usr/bin/convert` exists; `rsvg-convert`/`inkscape`/`magick` do not). NOTE: `logo-nome.svg` is a WHITE wordmark — never place it on white/cream; back it with a dark/brand-colored fill.
- Transactional emails (`src/server/email-templates.ts`) go through `renderBrandedEmail` — keep CSS fully inline (no `<style>`), pass RAW (unescaped) `name`/`url` (the helper escapes everything), and thread `publicAppUrl: env.PUBLIC_APP_URL` for the logo/footer links.
