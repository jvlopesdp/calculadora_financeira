## Codebase Patterns
(Add reusable patterns here as they are discovered. Patterns from the previous run — ralph/financing-tracker-foundations — are archived at scripts/ralph/archive/2026-06-02-financing-tracker-foundations/progress.txt and may still apply where the relevant code is unchanged.)

- Vite assets: anything in `public/` is served from the SPA root. Files moved to `public/brand/` become available at `/brand/<filename>` at runtime AND at build via `dist/client/brand/<filename>`. The Cloudflare Vite plugin includes the `public/` tree in the Worker's static assets — no Wrangler config change needed.
- Better Auth callbacks (`emailVerification.sendVerificationEmail`, `emailAndPassword.sendResetPassword`) receive `{ user, url, token }`. The library-generated `url` points at `/api/auth/*` which the SPA does NOT route — that's the source of the verify-email 404 bug. Rewrite the URL inside the callback BEFORE passing to the template, using `${env.PUBLIC_APP_URL}/<spa-route>?token=${token}`.
- Email logos: most email clients (Outlook especially) don't render SVG. Always host a PNG export at `public/brand/email-logo.png` and reference via absolute URL `${PUBLIC_APP_URL}/brand/email-logo.png` (relative paths don't work in email).
- Email HTML: inline CSS only, no `<style>` blocks; explicit `width`/`height` attrs on `<img>` (Outlook ignores CSS for image sizing); max-width:600px container; safe font stack `-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, sans-serif` (no webfonts).
- Brand palette: `#B94F45` (primary/CTA), `#E7A93F` (mostarda/destaques), `#CBBBA3` (bege/superfícies suaves), `#F7EFE2` (creme/backgrounds), `#1F1F1F` (texto), `#7A7A7A` (footer texto).
- Logo breakpoint: `< md` (Tailwind 768px) → `<BrandMark />` compacto; `≥ md` → `<BrandLogo />` horizontal completo. Justificativa: abaixo de 768px o logo horizontal compete por espaço com o trigger de menu mobile e o nav-user.
- Session detection at `/`: reuse `useSession()` from `src/lib/queries/session.ts` (introduced em ralph/financing-tracker-foundations US-003). It's the single source of truth for client session state and returns `{ user, session, isPending, isError }`. Don't reintroduce `authClient.useSession` outside `src/features/auth/**`.
- `useSession` mocking GOTCHA (carried over): tests rendering any subtree that includes `NavUser` need to mock BOTH `useSession` AND `useSignOut` from `@/lib/queries/session`, otherwise vitest throws "No useSignOut export is defined on the mock". Same applies to anything importing from this module.
- Router: routes live in `src/app/routes.tsx`. The wildcard `*` route is `<NotFoundPage />` — any request to an unknown URL renders 404 (incl. `/api/auth/verify-email` if Better Auth ever serves SPA-fallback HTML for that endpoint, which is what was happening in the bug). Adding a new public route requires registering it in routes.tsx; protected routes go inside `<ProtectedRoute>` block.
